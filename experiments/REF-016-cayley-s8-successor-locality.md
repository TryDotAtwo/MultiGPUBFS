# REF-016: real Cayley successor duplicate locality

Date: 2026-08-28 (Europe/Moscow)  
Status: pass; locality depends strongly on frontier order and expansion layout

## Question

Where do duplicate successor states actually co-locate in an exact Cayley-graph
BFS, and do the synthetic locality profiles from REF-014/015 represent real
frontier batches?

## Graph and exact BFS

The graph is the undirected Cayley graph of `S8` generated by the seven adjacent
transpositions. A state is an eight-element permutation and its exact dense key
is its Lehmer rank in `[0, 40320)`. Rust performs complete level-synchronous BFS
from the identity in Docker.

Correctness gates:

- exhaustive Rust unit test proves the rank function is a bijection over all
  40,320 permutations;
- full traversal reaches 40,320 states, diameter 28 and peak frontier 3,836;
- total generated transitions are 282,240;
- exact batch duplicate occurrences are 201,602;
- each row checks
  `generated = batch_duplicates + unique_visited_hits + accepted`;
- all layout/order variants have identical exact BFS counts at every depth.

The retained Rust artifact validator reports:

```json
{"status":"pass","validator":"rust-ref016-artifact-v1","rows":174,"exact_depth_groups":29,"layout_order_groups":6}
```

## Layouts and orders

The same mathematical frontier is represented three ways:

- `rank-sorted`: increasing Lehmer rank, as a bitmap scan could produce;
- `discovery`: first-acceptance order from parent-major level expansion;
- `hash-shuffled`: deterministic SplitMix64 ordering, representing destroyed
  neighborhood locality without adding nondeterminism.

Each is expanded in two ways:

- `parent-major`: all seven generators for parent 0, then parent 1, etc.;
- `generator-major`: generator 0 for every parent, then generator 1, etc.

## Metrics

For each level and ordering the experiment records:

- global exact duplicate occurrences and maximum multiplicity;
- claims removable by equal-key aggregation in each consecutive 32-item warp;
- the analogous oracle potential inside each 256-item block;
- distinct-key collisions on the same 32-bit bitmap word inside a warp;
- warps/blocks containing at least one equal key.

`equal_key_block_savings` is an opportunity bound, not the block compaction from
REF-014. Realizing it requires a block-local exact set and its cost is not yet
measured.

## Aggregate result

All rows contain 282,240 candidates and the same 201,602 global duplicate
occurrences.

| frontier order | layout | warp equal-key savings | % generated | % global duplicates | block equal-key savings |
|---|---|---:|---:|---:|---:|
| discovery | parent-major | 48,713 | 17.26% | 24.16% | 109,862 |
| rank-sorted | parent-major | 28,290 | 10.02% | 14.03% | 83,760 |
| hash-shuffled | parent-major | 861 | 0.31% | 0.43% | 7,364 |
| discovery | generator-major | 31 | 0.01% | 0.02% | 754 |
| rank-sorted | generator-major | 32 | 0.01% | 0.02% | 794 |
| hash-shuffled | generator-major | 57 | 0.02% | 0.03% | 1,116 |

At the peak frontier (depth 14), parent-major discovery order exposes 4,563
warp-local duplicates and 10,340 block-local duplicates out of 26,852
candidates. Hash-shuffling reduces those to 55 and 370 while preserving the
same 19,380 global duplicates.

Bitmap-word collisions also depend on representation. Across the traversal,
rank-sorted parent-major has 196,283 same-word excess accesses inside warps;
discovery has 139,194 and hash-shuffled 78,922. These are not equal-key savings:
different bits in the same word still issue distinct `atomicOr` operations and
may serialize.

## Findings

1. **Frontier order is a performance state.** It does not change BFS distances
   or sets, but it changes whether algebraically identical successors meet in a
   warp by more than 56x between discovery and hash-shuffled parent-major order.
2. **Expansion layout can erase locality.** Every Cayley generator acts as a
   bijection, so successors within one generator-major slice are unique. Most
   duplicates arise across different generators and are separated by an entire
   frontier; only slice boundaries occasionally share a warp or block.
3. **Parent-major is structurally favorable for local dedup.** Related parents
   and different generators can produce the same child close together, but the
   magnitude depends on how the frontier itself was produced.
4. **Atomic output order can destroy the next level's optimization.** A kernel
   that wins one level by cheaply appending accepted states may randomize the
   next frontier enough to lose warp aggregation. Kernel-local timing therefore
   misses a cross-level consequence.
5. **Sorting has a second possible value.** REF-015 found global sort too costly
   when used only for dedup. Ordering a frontier may nevertheless pay if it
   improves successor generation, bitmap locality, owner routing, or several
   subsequent stages. This requires an end-to-end level experiment.
6. **Global duplicate ratio remains insufficient.** All six configurations
   have 71.43% global duplicate occurrences overall, while warp-removable
   fractions range from 0.01% to 17.26% of candidates.

## Corrected near-miss

The first version measured only rank-sorted frontiers and appeared to establish
28,290 warp-local savings for parent-major expansion. Inspection showed that
the ordering came from scanning keys in rank order, not from BFS semantics.
That hidden assumption was not accepted as a general conclusion. The artifact
was replaced by v2 with discovery and hash-shuffled controls. This correction
changed the observed parent-major total from 861 through 48,713 without changing
one exact BFS count.

## Boundaries

- This is exact locality accounting, not a GPU throughput measurement.
- `S8` frontier batches are too small to establish large-GPU saturation.
- Discovery order here is deterministic Rust first-acceptance order; concurrent
  GPU atomic compaction may produce another order.
- The chosen generators have strong Coxeter relations. Other Cayley graphs need
  separate measurement.
