## Mathematical state contract

The current config contains the identity vector `[0,1,...,119]` as its central
state and 24 named permutations of the 120 positions. The host and CUDA action
convention is destination gather:

```text
child[p] = parent[generator[p]].
```

Because all 120 central values are distinct, the state reached by a permutation
uniquely identifies that permutation. No nonidentity generated permutation can
fix the identity vector. Therefore this particular representation is a genuine
Cayley graph of the subgroup generated by the 24 moves, not a color-state
Schreier quotient. This does not assert that the subgroup is all of `S120`.

There was no canonicalization, rotational quotient, or partial-state projection
on the inspected state-generation path. Padding is cleared separately and is
not part of the 120 logical positions.

## Equality boundary in native CayleyPy

Native CayleyPy generates full states but `get_unique_states` sorts scalar
hashes and retains the first row for each distinct hash. It does not compare
full states inside an equal-hash run. For this 120-entry encoded state, the
hasher is not the identity path; it produces an `int64` hash.

Therefore its BFS recurrence is exact conditional on no unequal states sharing
a hash. The code provides a very low collision-probability mechanism, not a
deterministic proof of injective state identity. No collision was observed by
REF-025, but the retained layer counts alone cannot prove absence at unrecorded
depths.

## Equality boundary in the production beam pipeline

The production host representation stores 120 logical bytes in a padded state,
and goal comparison can inspect full bytes. Candidate routing and Stream4 dedup,
however, carry `Hash128` in `CandidateMeta`; CPU Stream4 and CUDA
`ReduceByKey` merge candidates by the 128-bit hash key without materializing and
comparing both full candidate states.

This is separate from beam pruning:

- beam width already means the production search is not exact BFS;
- hash-only dedup adds a probabilistic state-identity assumption even within
  the retained beam;
- full replay validation can validate a returned path but cannot prove that no
  useful candidate was lost earlier to a hash collision.

No actual 64- or 128-bit collision was found. This audit identifies the proof
boundary; it is not a bug report or an instruction to redesign the pipeline.
