# Native Macro-Lookahead Multi-GPU BFS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an exact, preallocated native matrix-Cayley BFS whose user-selected `macro_depth` compiles children, grandchildren and deeper products into one stacked GEMM, then validate and benchmark it on non-toy finite groups and publish replayable Parquet results.

**Architecture:** Macro products are deterministic shortlex transitions carrying their original word length. One GEMM emits weight-grouped candidates; future depth buckets are provisional and become immutable only when settled in increasing original BFS depth. Owner ranks retain a checked `2*effective_macro_depth` settled-hash window and fixed-capacity future arenas, route only contiguous sorted ranges, and never allocate or switch profiles in the hot loop.

**Tech Stack:** Rust 1.75 host/contracts, C++17/CUDA, CUTLASS sm75 INT8 Tensor Core GEMM, CCCL/CUB, NCCL, Kaggle 2xT4, Parquet/Hugging Face datasets.

**Spec:** `docs/matrix-runtime-architecture-v2.md`

## Global Constraints

- Branch `codex/native-matrix-bfs`; CayleyPy baseline `f0f2b8e` remains unchanged.
- `macro_depth` has no policy ceiling; checked integer, ABI, GPU, RAM and disk capacities decide admissibility before depth zero.
- `macro_depth=1` is behaviorally identical to the validated DENSE/CUB runtime.
- Exactness is relative to the original unit-cost generator set, conditional only on the existing Hash128 collision policy.
- All large device, pinned-host, route, future, history and archive extents are fixed before execution; overflow is fatal.
- Full archives and failed trials remain evidence; no fallback or hindsight mode switching.
