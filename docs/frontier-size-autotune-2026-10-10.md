# Frontier-size tuning, 2026-10-10

The general distributed exact GPU engine now keeps separate profiles by parent-frontier size. A small profile uses matched prefix measurements already collected by startup tuning; it never repeats BFS to build the size table. Unsupported or short/tiny workloads retain the conservative path. A large unmeasured range is explicitly `UNMEASURED_CONSERVATIVE_PROFILE`, rather than extrapolated from small layers.

As the real frontier grows, the engine samples actual work chunks once per logarithmic size bucket. Candidates are the admitted maximum batch and one quarter of it, and CUDA/GEMM when the matrix graph and native workspace admit exact GEMM. Candidates run forward then in reverse order. Each parent chunk is processed once, including generation, hashing, routing, communication and exact deduplication. No replayed graph, CPU state generation, CPU deduplication, state downloads, SSD checkpoint or buffer reallocation is introduced. Only existing frontier metadata and bounded timing/error scalars pass through the host. Pilot boundaries synchronize owner streams; after the short sampling window, asynchronous production resumes. A ten-percent margin avoids marginal live switches. Queue-overflow retry aborts the sampling window instead of repeatedly restoring an overflowing test batch. Resource-error observations are not accepted as timings.

Live chunks are disjoint, normalized by processed parent count, with a common collective maximum time. This is an empirical online heuristic, not an identical-work whole-layer benchmark or a global optimum proof. All ranks agree on the winner through collective scalar timing. Cache entries keep their evidence type distinct (`LIVE_CHUNK_EMPIRICAL_PROFILE` versus matched prefix). Profiles switch only at safe chunk/layer boundaries. Shrinking frontiers use their own cached bucket, not the last large profile. Shared-host cache reuse validates graph, native implementation/dependencies, hardware/topology, configuration and admission geometry. Exact cached frontiers initialize native bucket choices without another trial. External ranks use consistent collective profiles and an in-run bucket cache; cross-run external caching is not claimed.

Shard partition, history representation, transport layout and physical queue capacities remain fixed during a run. They still belong to initial admitted geometry selection. Switching these representations would need an explicitly validated repartition/history conversion. The legacy specialized SHARD_AB reference backend retains its static startup profile; this feature is implemented in the general GPU engine. The explicit `backend="generic"` contract remains enforced. A new native capability receipt prevents old binaries from silently pretending to apply size profiles. GEMM workspace may be reserved while CUDA is selected: serialized plan `generator_backend` denotes the allocated capability, while size profiles/live events record the actual generator choice.

Startup uses a soft shortlist allowance of min(8 seconds, ten percent of the requested run time), one-second pilots and at least two baseline alternatives when admitted. Initialization/admission and completing a started GPU layer can exceed this soft allowance; it is not a universal wall-clock guarantee. Tuning time is deducted from the requested production time. Short runs do not perform extra size/capability probes.

## Validation

On cheap 2xRTX3060: 510 Python tests passed with one conditional skip, followed by targeted tests covering explicit generic selection, short-run bypass, size separation, unknown ranges and cache preservation; 19 Rust library tests passed. Four actual complete matrix-encoded S8 runs (one/two GPUs, HASH/SORTED histories) matched all CPU distance layers. Terminal/current and preceding-small payloads were independently checked. A cached live-bucket replay completed without new trial events. Two independent external rank processes completed the same exact graph with the updated native capability.

Large LRX12 runs with equal capacity, shard geometry and transport were compared on their common completed prefix. Both were resource-limited INCOMPLETE; these are not full graph times.
