# BFS dominating sets, covering radius, and k-center certificates

Multi-source BFS exactly evaluates how well a **fixed** set of centers covers an
unweighted graph. Choosing a smallest or best center set is a different,
combinatorial optimization problem. Confusing these two roles makes a correct
distance traversal look like an optimizer that it is not.

No optimizer, production implementation, benchmark, or GPU code is added.

## 1. Distance to a fixed center set

Let `G=(V,E)` be a finite undirected unweighted graph and let nonempty
`C subseteq V`. Define

```text
d(v,C) = min_(c in C) d(v,c),
rho(C) = max_(v in V) d(v,C).
```

Seeding every distinct center at depth zero in one multi-source BFS computes
all `d(v,C)` exactly. The last nonempty distance layer is therefore the
covering radius `rho(C)`, provided every vertex in the declared universe is
reached.

The scalar result does not require a nearest-center owner. Voronoi tie-breaking
can change owner cells and load assignment, but cannot change `d(v,C)` or
`rho(C)`.

## 2. Domination is radius-one coverage

The closed neighborhood is `N[c]={c} union N(c)`. A set `C` dominates `G` iff

```text
V = union_(c in C) N[c].
```

Equivalently, `rho(C)<=1`. More generally, an `r`-distance dominating set
satisfies

```text
V = union_(c in C) B_r(c),
```

or `rho(C)<=r`. Thus ordinary domination and distance domination are coverage
questions in the graph metric generated by BFS.

For a fixed `C` and `r`, a complete multi-source BFS gives a simple decision
certificate:

- every vertex reached by depth `r` proves coverage of the declared finite
  universe;
- a vertex with `d(v,C)>r`, or unreachable from all centers, witnesses failure.

An empty frontier is not enough when the state universe is incomplete,
implicitly truncated, or partition reports are missing.

## 3. Evaluation is not selection

Three questions must remain separate:

```text
evaluation:             compute rho(C) for a supplied C;
minimum r-domination:   minimize |C| subject to rho(C)<=r;
graph k-center:         minimize rho(C) subject to |C|<=k.
```

One multi-source BFS solves the first question in linear graph-traversal work.
It does not decide which center set to try. Minimum distance domination is a
set-cover problem over graph balls, while k-center searches over placements of
at most `k` balls and their radius.

Repeated BFS calls can serve as an evaluation oracle inside exhaustive search,
a heuristic, or an approximation algorithm. The guarantee then belongs to the
outer selection method plus the exactness of each traversal, not to BFS alone.

## 4. Degree is not eccentricity

Choosing a maximum-degree vertex is not an exact graph-center rule. Consider
the path `0-1-2-3-4` with three extra leaves adjacent to `0`. Vertex `0` has
unique maximum degree four, but eccentricity four. Vertices `1` and `2` each
have eccentricity three and are optimal one-centers.

Degree describes the radius-one frontier. Eccentricity is the maximum over all
BFS depths. A large first ball need not minimize the last distance.

## 5. Farthest-first is useful but not exact

The farthest-first traversal starts from a chosen center and repeatedly adds a
vertex farthest from the current center set. Each iteration can use one
multi-source BFS to recompute nearest-center distances.

On the six-vertex path, starting at endpoint `0` and asking for two centers
selects `{0,5}` and has radius two. The exact optimum is `{1,4}` with radius
one. Therefore farthest-first is not an exact k-center algorithm and depends on
the initial/tie contract.

For a metric, its classical guarantee is nevertheless a factor of two. Let the
final greedy radius be `R`, and add a farthest witness to the `k` chosen
centers. These `k+1` points are pairwise at least `R` apart. If `R>2 OPT`, two
of them must lie in the same one of `k` optimal radius-`OPT` balls, yet the
triangle inequality would put them at distance at most `2 OPT`, a
contradiction. Hence `R<=2 OPT`.

The path example attains this factor exactly: greedy radius two, optimum one.

## 6. Upper and lower certificates

A proposed center set `C` plus complete multi-source distances proves the upper
bound

```text
OPT_k <= rho(C).
```

To prove that a radius `r` is impossible with `k` centers, it suffices to give
`k+1` vertices pairwise farther than `2r`: one radius-`r` ball cannot contain
two of them. This packing witness proves `OPT_k>r`.

Exact optimality needs matching evidence. A good center set alone supplies only
an upper bound; a separated packing alone supplies only a lower bound. BFS can
verify the distances used in either certificate, but does not conjure the
certificate set.

## 7. Disconnected and directed graphs

In a disconnected undirected graph, any component without a center has
`d(v,C)=infinity`. The covering radius is therefore infinite, not the maximum
finite distance among reached vertices. An implementation that reduces only
reached labels silently returns the wrong coverage answer.

For directed graphs, forward multi-source BFS computes

```text
min_(c in C) d(c,v).
```

If coverage means that every vertex can reach a facility, the desired value is
`min_c d(v,c)` and the BFS must run from `C` in the reversed graph. Domination
also has distinct in-, out-, and underlying-undirected conventions.

## 8. Cayley and Schreier graphs

In a finite undirected vertex-transitive Cayley graph, every singleton center
has the same eccentricity. Translation can normalize one selected center to
the identity, so the `k=1` placement question is trivial once the generator
metric is fixed.

For `k>1`, relative center positions still matter. A common translation fixes
one center but does not erase pairwise word distances among the rest. Generator
changes alter the balls and therefore both domination and k-center objectives.

The same root symmetry may hold for a transitive Schreier graph, but state
identity, stabilizers, and action direction remain part of the contract.

## 9. GPU and multi-GPU boundary

Parallel hardware can accelerate evaluation of a fixed center set. A complete
run must account for:

- deduplicated depth-zero sources;
- exact visited membership across all owner partitions;
- reached count and unreachable count;
- maximum finite distance only after proving no vertex is missing;
- optional owner labels and their tie semantics;
- generated edges, accepted states, routing bytes, synchronization rounds, and
  end-to-end time as separate quantities.

An iterative center-selection method performs several traversals. Reporting
only the fastest BFS iteration hides the number of evaluations and the outer
algorithm's selection quality. Single-GPU and multi-GPU throughput do not
change the approximation or optimality proof.

## 10. Docker/Rust probe

`experiments/graph_covering_bfs_probe.rs` uses transparent adjacency lists,
multi-source BFS, and exhaustive subset enumeration only on tiny fixtures. In
Docker with Rust 1.85 it confirmed:

```text
degree trap: maximum-degree radius 4; exact one-center radius 3
P6, start 0: farthest-first centers [0,5], radius 2
P6 exact two-center: centers [1,4], radius 1
disconnected graph, centers [0]: covering radius None
```

The enumeration is a correctness witness for these fixtures, not a proposed
solver or performance result.

## Takeaway

Multi-source BFS turns a proposed center set into exact distances and a
covering-radius certificate. Domination and k-center ask for the center set
itself, which is an outer optimization problem. BFS is the evaluator and
distance witness; it is not, by itself, the selector.
