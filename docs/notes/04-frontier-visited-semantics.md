# Frontier, candidates, and visited are different objects

Status: conceptual study pass, 2026-08-28.

## Why the distinction matters

In informal descriptions, BFS often appears to have only a queue and a visited
set. That is sufficient for pseudocode but hides four logically different
objects:

```text
current frontier     vertices whose outgoing edges must be expanded now
candidate occurrences every generated edge endpoint, including repetitions
candidate set         distinct endpoints generated by the current frontier
next frontier         candidates not already in the completed visited ball
```

For a completed ball `B_d` and frontier `F_d`:

```text
C_occ(d) = bag of endpoints of all edges leaving F_d
C_set(d) = support(C_occ(d))
F_(d+1)  = C_set(d) minus B_d
B_(d+1)  = B_d union F_(d+1)
```

Only `F_d`, `C_set(d)`, and `B_d` are mathematical sets. The occurrence bag has
multiplicity and often dominates physical work. An implementation that reports
only the number of accepted vertices erases most of what happened.

## Frontier is a boundary, not merely a work list

`F_d` has two meanings at once:

1. **metric sphere:** every member is exactly distance `d` from the source;
2. **unpropagated boundary:** these are the vertices whose outgoing transitions
   have not yet been used to construct the next ball.

The second meaning explains why retaining only visited is insufficient to
continue efficiently. `B_d` says what is known but not which part of that
knowledge still needs expansion. Conversely, retaining only the frontier loses
the history needed to reject paths that return to earlier layers.

After `F_d` is fully expanded it may be discarded for reachability/distance-only
BFS, because its membership remains represented in `B_d`. It cannot always be
discarded when the output requires parents, all shortest paths, path counts,
backtracking, or checkpoint reconstruction.

## Visited is a certificate, not a cache

At a correct level boundary, `visited = B_d` means:

> for every stored vertex, BFS possesses a path witness of length at most `d`,
> and every vertex with true distance at most `d` is stored.

This is stronger than “we have seen this hash before.” A false positive changes
the proven ball by deleting a reachable vertex. A false negative changes the
work representation and may also break capacity, but if exact dedup happens
later it need not change the mathematical result.

This asymmetry is useful:

- false positive visited answer: potentially incomplete BFS;
- false negative visited answer: duplicate work, conditionally recoverable;
- collision-resolving hash table: exact despite hash collisions;
- Bloom filter alone: not exact, because its positive answer is ambiguous;
- Bloom filter before an exact backing set: safe only when positives are
  confirmed rather than rejected directly.

Visited can therefore be compressed only with a proof that membership remains
exact for the adopted vertex identity.

## White, gray, and black states

The classical three-color interpretation separates scheduling from discovery:

```text
white  not discovered
gray   discovered, but not fully expanded
black  fully expanded
```

In a level-synchronous implementation:

- `F_d` is gray;
- earlier frontiers are black;
- `B_d` is gray union black;
- accepted `F_(d+1)` becomes gray for the next round.

A two-state visited bit merges gray and black. This is sufficient for ordinary
single-source distances because both must reject rediscovery. It is insufficient
when the algorithm needs to ask whether a vertex is merely pending or already
expanded, for example in asynchronous traversal, checkpoint recovery, dynamic
graph updates, or some termination protocols.

Thus one bit can implement a particular BFS contract; it is not a universal
model of traversal state.

## A phase-accurate level

It helps to name the transitions within one level:

```text
1. F_d is complete and included in B_d.
2. Expand every required transition from F_d.
3. Obtain occurrence bag C_occ(d).
4. Collapse equal vertex identities to C_set(d), explicitly or implicitly.
5. Subtract exact B_d.
6. Materialize every member of F_(d+1), with overflow impossible or explicit.
7. Commit F_(d+1) into B_(d+1).
```

Physical implementations may fuse or reorder operations 3-7. Correctness is
preserved only if the result is observationally equivalent to the set equation.
For example, an atomic visited claim fuses batch deduplication, subtraction from
`B_d`, and commitment to `B_(d+1)`. A sort/unique pipeline makes stage 4
explicit. Owner-computes distributed BFS moves stage 4 across source and owner
partitions before the authoritative stage 5.

## Duplicate taxonomy

“Duplicate ratio” conflates distinct causes and removal locations.

### Repeated generator occurrence

One parent produces the same child more than once because generators are
identical, act identically on this state, or include an identity. This can
sometimes be removed before general visited lookup.

### Convergent parents

Different parents in `F_d` produce the same child. This is a property of graph
structure and multiple paths, not an erroneous repeated edge.

### Current-layer hit

A candidate already belongs to `F_d`. Self-loops and same-level edges cause
this. It must be rejected because the current frontier is already part of
`B_d`.

### Earlier-layer hit

A candidate belongs to `B_(d-1)`. It represents a non-shortest return path.

### Cross-partition convergence

Different source ranks or GPUs generate the same owner key. Local dedup cannot
see the equality; it becomes visible only after routing to a common authority.

### Representation collision

Two different vertices map to the same non-injective key or hash. This is not a
graph duplicate at all. Treating it as one is a correctness bug.

These categories can have the same final symptom—candidate not entering the
next frontier—but imply different algorithms, costs, and proofs.

## Set, multiset, sequence, and partitioned frontier

The mathematical frontier is a set. Its physical representation may expose
additional structure:

- **sequence:** order affects which shortest parent wins and where related work
  appears in memory;
- **multiset:** duplicates remain temporarily and must not be expanded as if
  they were distinct vertices indefinitely;
- **bitmap:** order disappears, membership and dense scanning become natural;
- **partitioned set:** ownership and communication location become part of the
  representation;
- **state array:** necessary when neighbors cannot be regenerated from a dense
  ID alone;
- **ID array:** sufficient when ID-to-state/adjacency is available.

Confusing representation properties with BFS semantics causes two opposite
mistakes: assuming order matters for shortest distances, or assuming order has
no observable consequences at all.

## What order inside a layer can and cannot change

For a complete exact level, arbitrary permutation of `F_d` cannot change:

- the set `C_set(d)`;
- `F_(d+1)`;
- shortest-distance labels;
- reachable component;
- the number of mathematical vertices in each layer.

It can change:

- which shortest parent is retained;
- the first target occurrence and early-stop work;
- temporary multiplicity and buffer pressure under streaming dedup;
- locality of candidate identities and visited words;
- distribution of work among threads/ranks;
- the sequence order of `F_(d+1)`, which affects later levels;
- reproducibility of logs and parent trees.

REF-016 demonstrated the distinction sharply: six representations of the same
S8 frontiers had identical 201,602 global duplicate occurrences, while
warp-local equal-key opportunities ranged from tens to 48,713.

## The frontier has width and volume

Two size measures answer different questions:

```text
width_d  = |F_d|
volume_d = sum of generated degree over vertices in F_d
```

For regular Cayley graphs, `volume_d = |S| * width_d`. For irregular explicit
graphs, equal-width frontiers can differ enormously in work. Selecting a side
in bidirectional BFS by smaller vertex count is therefore only a proxy; outgoing
edge volume can be the more relevant quantity.

Candidate multiplicity adds another dimension:

```text
unique expansion pressure = |C_set(d)|
physical generation work  = |C_occ(d)|
acceptance                 = |F_(d+1)|
```

No one scalar describes frontier cost.

## Peak frontier and peak candidates are different limits

Visited memory grows monotonically, but frontier memory can rise and fall.
Candidate storage, if materialized, may peak at a different level from frontier
width because degree and filtering vary.

An implementation can therefore fail despite the final reachable set fitting:

- visited fits, candidate bag does not;
- frontier fits mathematically, duplicate occurrences overflow an append buffer;
- every rank fits in aggregate, but one owner partition overflows;
- output keys fit, but parent/state records do not.

Exact capacity accounting belongs to the algorithm contract. “We would have
deduplicated them later” does not recover a candidate silently dropped before
that stage.

## Explicit and implicit graphs need different frontier payloads

In an explicit CSR graph, a dense vertex ID normally suffices to locate the
adjacency interval. The frontier can be an ID list or bitmap.

In an implicit graph, expansion applies transformations to a state. A rank may
provide exact visited membership yet still be insufficient to reconstruct the
state cheaply. The frontier may need:

- full state;
- rank plus an efficient unranking procedure;
- a compact reversible state encoding;
- state plus parent/move metadata.

Consequently “one integer per frontier vertex” is not a representation-neutral
assumption. Cayley graphs make this visible: a Lehmer rank is bijective, but
applying a generator directly to a permutation can be cheaper than repeatedly
unranking it.

## Pull changes the meaning of the active set

Push BFS iterates `u in F_d` and emits outgoing neighbors. Pull BFS iterates
unvisited `v` and asks whether any predecessor lies in `F_d`. The mathematical
next frontier is the same, but the physically enumerated universe changes from
frontier edges to unvisited vertices.

This requires:

- an enumerable unvisited vertex universe;
- efficient frontier membership queries;
- predecessor access or reversible adjacency;
- a frontier large enough that scanning unvisited vertices is worthwhile.

An implicit graph having inverse generators satisfies only the predecessor
part. Without cheap enumeration of all unvisited states, the usual pull
advantage may be inaccessible.

## Distributed visited is an ownership statement

If visited is sharded, “is `v` visited?” has one authoritative location. A
stable owner function turns global set membership into owner-local membership:

```text
owner(v) stores the definitive visited bit/record for v
```

Before routing, a source can remove local duplicates but cannot safely decide
that another source did not generate the same state. After routing, the owner
can merge all occurrences and make one exact first-discovery decision.

This gives distributed frontier processing a semantic sequence:

```text
generate locally -> optional local dedup -> route by owner
-> owner dedup/visited -> form owner-local next frontier -> global level decision
```

Changing where equality converges changes communication and memory pressure,
but not the required global set equation.

## Questions to ask whenever “frontier” appears

1. Is it the exact set, an occurrence bag, or a sequence with duplicates?
2. Does it contain full states, IDs, ranks, or parent records?
3. Is the current frontier already committed to visited?
4. Is the whole layer complete, or is it a streaming prefix?
5. What happens when capacity is reached?
6. Who is authoritative for membership?
7. Is order observable through parents, stopping, locality, or routing?
8. Does the next operation enumerate frontier edges or unvisited vertices?

These questions usually reveal more than asking whether the frontier is a queue,
vector, bitmap, or hash set.
