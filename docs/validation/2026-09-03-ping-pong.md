# Two-slot generation/consumer boundary

Development scope: one GPU, one owner bucket. This is not the roulette shard
scheduler, archived runtime or a multi-rank implementation.

## Accepted semantics and implementation choice

The architecture permits bounded overlapping slots without a host barrier
inside a depth. `new_pipelined` selects two slots before allocation;
`new` retains the serial reference path. Neither changes mode during a run.
Generation and hash use one nonblocking producer stream. Sort, owner commit
and materialization use one nonblocking consumer stream, retaining a single
writer for all persistent owner/frontier metadata.

Let C = parent_batch * moves and S = align_up(state_bytes,16).

| Region | Shape/bytes | Writer | Readers | Reuse condition |
|---|---|---|---|---|
| Children | u8[2,C,S], 2*C*S | producer, selected bank | consumer materializer | released[bank] |
| Hashes | Hash128[2,C], 2*C*16 | producer, selected bank | consumer sort | released[bank] |
| Origin refs | u64[C], C*8 | constructor | consumer sort | read-only entire run |
| Sort/owner/materialize scratch | unchanged fixed plans | consumer | consumer | same-stream order |

All device spans are cudaMalloc-aligned; bank offsets are multiples of 16.
Generation/hash scratch is shared across banks but belongs only to the producer
stream. No second copy of those library plans is required. Additional explicit
payload over serial is C*(S+16) bytes, plus four CUDA event handles and one stream
whose driver storage is not included in this payload formula. A complete native
allocation/reserve planner remains an open gate.

For epoch e, bank=e%2. If e>=2, the producer waits on the release recorded for
e-2. It then generates/hashes and records ready[bank]. The consumer waits on
that ready event, sorts, commits, materializes and records released[bank]. All
waits are submitted after their corresponding record call; no wait depends on
a future host record. First use in a depth needs no release wait because the
previous depth has drained. Counts stay on device between batches.

CUDA event re-recording does not retarget an already submitted wait:
[NVIDIA event record contract](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__EVENT.html).
Successful finalization waits on the consumer, transitively draining every
producer batch. On errors, Drop drains both streams before freeing buffers or
events. A fatal owner status prevents frontier publication and poisons the
executor; accepted states are not silently rolled back or reused as a result.

## Evidence and remaining risks

The RED test failed on the missing pipelined constructor. The implementation
then passed full-layer CPU comparisons for (n,m,batch)=(3,3,1),(4,2,7),(4,3,64),
pre-dedup OFF/ON. These cases include padded states, repeated bank reuse,
partial tails and complete exhaustion. A separate capacity fixture fails with
multiple batches queued and verifies sticky errors and safe destruction.

The independent full U4 sweep also passed for m=2..6, seeds 0/1/20260828,
pre-dedup OFF/ON, batch 257: 30 configurations, every depth through exhaustion.
The six smaller configurations and fatal fixture are the sanitizer scope;
`full_u4_pipelined_sweep` is explicitly excluded from sanitizer invocations.
CPU contracts (25) and the unchanged serial full-state sweep passed again.

Nsight Systems on the local RTX 3070 captured 326 positive-duration overlaps
between kernels on different streams within the same process/device/context.
Examples include consumer CUB radix sort overlapping producer parent packing,
CUTLASS GEMM, modular materialization and hash epilogue. This establishes real
concurrent kernel execution for this small trace, **not** end-to-end speedup,
maximum occupancy or performance at production scale.

Raw trace: `test_results/nsys-ping-pong/trace.nsys-rep` and `trace.sqlite`.
The overlap query joins `CUPTI_ACTIVITY_KIND_KERNEL` to itself with
`a.streamId < b.streamId`, equal device/context/globalPid, and
`a.start < b.end AND b.start < a.end`. Kernel names were resolved through
`StringIds`. All files remain local/ignored.

The first sanitizer invocation completed all four tools with zero errors,
but its shell wrapper failed afterward because it was edited while executing.
That wrapper exit is not counted as a clean script pass. The unchanged-script
rerun completed with exit 0 and zero errors/hazards/warnings in all four tools;
logs are in `test_results/native-sanitizer-ping-pong-final/`.

The audit followed the GPU architecture skill: persistent metadata remains
single-writer, candidate bank leases end only after materialization, and
explicit payload bytes are distinguished from unmeasured driver allocations.
Kaggle packaging is extended to include ping-pong and to allow 1800 seconds for
the previously timed-out serial racecheck; no new Kaggle run was launched for
this slice.

Real T4 validation remains open for this new mode. StateRing reclamation,
shard roulette, asynchronous archive, NCCL and full production CLI remain open.
