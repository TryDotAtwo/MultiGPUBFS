# Experimental packed bitmap on eight RTX 3060 GPUs

This is an experimental source build based on public checkpoint
e0cf4098f06ca9a01b5c19f02952061a8845227c. It is not the released wheel and
does not change the default memory backend or strategy. The packed resident
codec is opt-in and currently supports permutation_bitmap with atomic only.
Warp, batch and full archive output are not established for this codec.

The eight-GPU host had RTX 3060 (SM86, 12 GiB each), driver 580.178.04,
CUDA 12.8 and NCCL 2.30.7, with four devices in each of two CPU NUMA domains.
The saved topology, GPU UUIDs, source files, binary/library checksums, raw
reports and scripts accompany this report. During the S12 measurement each
worker's /proc/PID/maps confirmed the actual executable, CUDA library, NCCL
and CUDA runtime paths. The exact executable and CUDA shared library were the
same measured binaries used on the two-GPU host:

- executable SHA-256: 9431576ff47f834be3c649cefcd9de9f5959379c0facb839317361e269bc6f87
- CUDA library SHA-256: e6d51a55218cea1b4685b16d0be31e2ce7ca6532388da9761b2ab749e3840ee1
- CayleyPy source: 2d35a8917ee1d123d6ec8c771bc08002c974a57f

## Correctness and persistence

Six small graph fixtures exercised the actual distributed native runtime on
eight devices. Each completed depth was compared as a complete multiset of
canonical states to an independently constructed CPU BFS. They included S4,
arbitrary signed symbols, repeated symbols, a directed action and coupled
position orbits, covering two- and three-bank presets, cyclic/page ownership
and exact/padded communication. The cap-sufficient S4 finished; a one-row
smaller cap returned RESOURCE_10 with the exact completed prefix. Within one
persistent pool, packed bitmap, ordinary bitmap and segmented hash were
switched and the same eight worker PIDs were retained. These are exact checks
for the stated small graphs, not proof for arbitrary graphs.

The same full-layer multiset checks, cap boundary, and persistent backend
switches also passed with eight shards on the same eight GPUs. This checks
small cases and does not by itself establish performance at scale.

The CayleyPy graph.bfs adapter was exercised from source with eight GPUs,
including repeated states, both presets and a cap-limited run, followed by
packed/unpacked switches with the same workers. All layer counts and the
complete terminal and penultimate states were checked. With autotune enabled,
both packed presets hit the intentionally tight cap, obtained a validated
resource-limited unmeasured profile from 11 and 13 pilots respectively,
returned an exact incomplete prefix, and ran a healthy subsequent job in the
same workers. This is not a large-graph measured autotuning acceptance.

A separate eight-GPU failure injection warmed and verified the actual
transport, then injected a rank-1 failure into the production BFS rather
than the preflight. It returned NATIVE_DISTRIBUTED_RANK_FAILED with the
rank's original marker and failure-evidence path in 11.93 s, and all old
worker processes exited. A new persistent group then completed S5 with
all layer counts and terminal/penultimate state sets checked. This covers
one injected rank failure, not every possible CUDA or NCCL failure. The
first test attempt accidentally injected into preflight; that interrupted
attempt and its logs are preserved separately. The test wrapper strips only
the fault-injection flags while the real preflight verifies/reuses its
transport evidence, then restores them for the target BFS.

## Comparison to the earlier dev44 run

The earlier complete S13 dev44 bitmap observation (500.51 s) was made
on a different eight-RTX-3060 node with driver 570.153.02 and a different
PCIe topology, in addition to different binaries, shard count, banks and
batch/recovery settings. It is historical context only, not a controlled
before/after measurement of this experimental build or a basis to attribute
the difference to packing.

## S12, eight GPUs, two banks

Four runs alternated ordinary/packed/packed/ordinary using the same native
binaries and persistent worker set. Each completed 479,001,600 states across
67 layers. Every layer count matched an independent Mahonian calculation; the
terminal and penultimate full state sets matched. Full state sets of the
intermediate large layers were not checked.

The same explicit max_capacity experiment used two banks, four shards, rows
per segment 1,048,576, four owner lanes, requested queue capacity 8192,
actual queue capacity 5632 on every rank, initial batch 4096, exact exchange and
batch recovery. These are recorded experimental
settings, not a claim that this is the automatically selected default.

| Frontier | BFS seconds | Depths 27–38 seconds | Frontier bytes/rank | NVML sampled maximum MiB/rank |
|---|---:|---:|---:|---:|
| ordinary SoA | 135.8157, 132.9757 | 74.5297, 72.9539 | 100,663,296 | 401, all ranks |
| packed u64 | 135.6371, 134.1135 | 75.4593, 73.9245 | 67,108,864 | 369, all ranks |

The window contains 277,885,890 new states and 3,013,839,301 generated
edges according to the independent layer oracle. Both codecs recorded two
source retries. Each rank allocated 7,484,400 bitmap bytes and 17,301,888
queue bytes and used a 2 GiB admission reserve; reserve is not an allocation.
Peak live rows by rank were [6343679, 6343679, 6455414, 6455414, 6455414,
6455414, 6343679, 6343679]. These per-rank maxima need not be simultaneous.
The original summary time-window slice was offset by one layer; the table uses corrected timings from the saved layer_seconds (index d-1 times depth d). NVML polling waits 0.5 seconds after each query; real intervals can be longer and can miss transient peaks.
This end-to-end comparison changes both packed storage and its route/owner
implementation; the observed runtime difference is within these repetitions'
spread and cannot be attributed to a single operation.

## Complete S13, eight GPUs, two banks

One ordinary run followed by one packed run used the same experimental
native binary, four shards, two banks, 1,048,576 rows per segment, four owner
lanes, initial batch 4096, requested queue 8192, actual queue 6144 on every
rank, exact exchange and batch recovery. Each completed all 6,227,020,800
states, and all 79 layer counts matched Mahonian numbers. The complete
terminal and penultimate state sets were checked; complete intermediate
large-layer state sets were not.

| Frontier | BFS seconds | Depths 34–44 seconds | Frontier bytes/rank | NVML sampled maximum MiB/rank |
|---|---:|---:|---:|---:|
| ordinary SoA | 2,052.5854 | 969.5910 | 981,467,136 | 1,327, all ranks |
| packed u64 | 2,003.9192 | 947.3575 | 603,979,776 | 967, all ranks |

For this chosen window the independent oracle gives 3,052,643,942 new
states and 36,412,333,584 generated edges. That is respectively
3.148/3.222 million accepted states/s and 37.554/38.436 million generated
edges/s for ordinary/packed. Each GPU allocated 97,297,200 bitmap bytes
and 18,874,752 queue bytes; the 2 GiB admission reserve is not an
allocation. NVML polling waits 0.5 seconds after each query; actual intervals can be longer and can miss short peaks. The source
retried twice in both runs; peak live rows are in the companion JSON and
are per-rank maxima that need not be simultaneous.

One observation per variant is not enough to establish a persistent timing
advantage or select a default. The original benchmark summaries used an
offset timing slice; this table recomputes the intended depths from the raw
layer timings (item d-1 records the creation of depth d). The unmodified
summaries and raw reports are retained in the evidence archive.

## Arithmetic capacity illustration, not a B200 test

For the full adjacent-transposition Coxeter graph, the independent script
scripts/mahonian_capacity_lower_bound.py computes all Mahonian layer
sizes for the command arguments 14 15. Assume a *dense visited bitmap* and two
frontiers containing precisely two adjacent layers. Ignore all rank skew,
alignment, queues, extra snapshots, CUDA, NCCL and allocator overhead:

| Graph | States | Max sum of two neighboring layers | Bitmap + unpacked frontiers | Bitmap + packed u64 frontiers |
|---|---:|---:|---:|---:|
| S14 | 87,178,291,200 | 7,455,084,376 | 115.268 GB | 70.538 GB |
| S15 | 1,307,674,368,000 | 101,253,107,976 | 1,682.256 GB | 973.484 GB |

GB above means 10^9 bytes. These are optimistic global storage bounds for
this storage scheme, not a guarantee that per-rank allocation will succeed.
The packed estimate assumes the experimental format applies and does not
include the extra memory required by archive snapshots. A real run requires
additional memory and can fail earlier on the most loaded rank. No S14/S15
or B200 execution is established by these estimates.

### Worst cyclic owner: exact layer distribution, idealized bytes

For identity-root S_n with all adjacent transpositions, lexical Lehmer ID,
eight GPUs and cyclic owner ID % 8, a separate dynamic program computes the
number of states in every depth and logical owner. Each Lehmer digit contributes
its value to inversion depth and digit * (k-1)! to the ID. The implementation
was checked against full independent lexical enumeration for S2–S8 with
1, 2, 3, 5 and 8 owners. Its two-live-layer peaks per rank agree exactly with
the measured eight-GPU S12 and S13 packed-run receipts above. This is a
mathematical model for this graph and owner mapping, not a hardware run of S14
or S15; an owner permutation can relabel the logical ranks.

The following maxima include a dense per-rank visited bitmap and the live
payload of two adjacent layers only. The unpacked row uses n bytes and the
experimental packed row uses eight bytes. GB is decimal 10^9 bytes.

| Graph | Largest one layer on a rank | Largest sum of adjacent layers on a rank | Visited bitmap bytes/rank | Ideal packed maximum GB/rank | Ideal unpacked maximum GB/rank |
|---|---:|---:|---:|---:|---:|
| S14 | 469,860,208 | 937,951,365 | 1,362,160,800 | 8.865772 | 14.493480 |
| S15 | 6,371,939,916 | 12,724,236,924 | 20,432,412,000 | 122.226307 | 211.295966 |

Segment rounding, unused reserved rows, queues, transient growth, archive
snapshots, CUDA/NCCL and allocator costs are excluded. In this specific S15
model, a single rank's largest layer exceeds 2^32 rows, so the configured cap
must remain per segment/bank rather than a cap on the whole GPU. The new
capacity has not been physically demonstrated at that scale. On an assumed
180 GB B200, 122.226 GB ideal packed storage leaves about 57.8 GB for all
excluded costs, but actual fit and speed require measurement on B200.

For the existing segmented hash with three resident banks and uncompressed
byte-per-symbol rows, the same layer counts give the following lower bounds
for states plus index alone. The sorted batch index uses 12 bytes per row;
the open-addressed hash uses at least two eight-byte slots plus an eight-byte
position per row. Power-of-two slot rounding, partially filled segments,
other buffers, and rank skew increase the actual requirement.

| Graph | Three neighboring live layers | Sorted-index hash minimum | Open-addressed hash minimum |
|---|---:|---:|---:|
| S14 | 11,141,606,753 | 289.682 GB | 423.381 GB |
| S15 | 151,421,412,675 | 4,088.378 GB | 5,905.435 GB |

These apply to the current three-bank storage contracts, not to every
possible exact BFS algorithm. Even the sorted-index lower bound for S15
exceeds 8 x 180 GB; S14 remains only an optimistic capacity calculation,
not a measured B200 acceptance.

For comparison, the same script gives a 2,615.349 GB dense visited bitmap
alone for the full S16 domain. That exceeds the nominal combined 1,440 GB
if all eight cards have 180 GB each, before any frontier or overhead.
This is a bound for this dense full-domain representation, not for sparse
visited schemes or unrelated graphs with a reduced closed domain.

## Output contract and open archive gate

The current segmented CayleyPy/graph-rank path reports exact layer counts and
writes bounded current/previous state samples. It does not expose a full
archive of all states at all depths through this path. The separate native
archive implementation exists elsewhere; its output behavior and archive
format have not been integrated or validated with the packed segmented path.
Consequently these tests establish neither full-layer archival nor path/edge
reconstruction. Do not interpret the small terminal samples as a complete
archive. Existing native output formats were not changed by this experiment.
