# dev40 GitHub wheel: two-GPU offline verification, 21 November 2026

[GitHub prerelease and assets](https://github.com/TryDotAtwo/MultiGPUBFS/releases/tag/native-pip-20261121-v40) contains the Python wheel and separate CUDA components for SM75/80/86/89/90/100/103/120 and universal. The compiled source commit is `82ac3180df1265992988149178975835f1c4c00b`. CI built all nine CUDA components, checked packaging contracts and published a matching executable/index. A separate existing whole-tree formatting CI check is not green; this is not a claim that every repository check passes.

On two physical RTX 3060 (SM86, driver 580.178.04), a clean Python 3.10 virtual environment installed the published wheel. `multigpubfs prefetch --sm 86 --json` downloaded the common runtime, native executable and SM86 component to a fresh cache. The subsequent GPU tests used `MGBFS_NATIVE_OFFLINE=1` and that cache, with no executable override.

The release wheel and native executable/CUDA component identified the same source commit. The executable SHA-256 was `1cecb6a63ee224bcb344db197b8ac6a73fb62ec762fef4f1427f51f6e5b9f328`; the SM86 CUDA library SHA-256 was `802c12e8e190881b88ca3caa59874f3c48923e6f82ed3c180df29d967bd2aabd`.

## Results

For each combination of segmented hash / permutation bitmap and atomic / warp / batch, the test ran three graphs: S4, directed C6 and a repeated-symbol permutation graph. It compared the exact state set at every completed depth against a CPU oracle, checked the preceding saved layer, and then required COMPLETE and matching layer sizes. Segment rows were three and bounded batch tile size two. The same two persistent worker PIDs were reused across graph and strategy changes. For both batch backends it additionally forced an INCOMPLETE capacity stop, verified its completed prefix, then completed a fresh graph using the same workers.

In a second clean Python environment, this ordinary direct install was executed successfully:

```bash
python -m pip install --upgrade "multigpubfs @ https://github.com/TryDotAtwo/MultiGPUBFS/releases/download/native-pip-20261121-v40/multigpubfs-0.2.0.dev40-py3-none-any.whl"
```

The corrected post-install smoke ran all six combinations on S3 with both GPUs and persistent workers in offline mode, each with exact layer sizes `[1,2,2,1]`. The first smoke attempt used an already-existing output directory and raised `FileExistsError`; the test harness was corrected to use a new child path, then passed. Both the failure and corrected test script and output are preserved.

A different optional source-install attempt, `pip install git+https://github.com/TryDotAtwo/MultiGPUBFS.git`, encountered repeated Git/GnuTLS checkout errors on this rental and was stopped. The wheel install above succeeded through GitHub; the source-install attempt is not counted as a pass. These are small-graph 2×SM86 tests of the Python `run_graph` and persistent-worker API, not physical B200 acceptance or proof for arbitrary graphs.
