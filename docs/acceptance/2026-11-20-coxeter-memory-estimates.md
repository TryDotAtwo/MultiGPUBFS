# S_n Coxeter: memory estimates for 8×B200

This is a sizing calculation, not a B200 run. NVIDIA lists 180 GB per B200 SXM and 1.44 TB per eight-GPU HGX B200 node ([NVIDIA specifications](https://docs.nvidia.com/enterprise-reference-architectures/hgx-ai-factory-h100-h200-b200/latest/components.html)). Actual available memory is smaller after CUDA/NCCL, queues, workspaces, allocation granularity and rank imbalance. We have not verified S14 on B200 or established optimal tuning.

The graph is specifically S_n generated by adjacent transpositions, starting at the identity. Its independent layer sizes are computed as the coefficients of product_{k=1..n}(1+x+...+x^(k−1)). A different generating set can have very different layer widths.

| n | total states | layers | largest single layer | largest sum of 2 adjacent layers | largest sum of 3 adjacent layers |
|---:|---:|---:|---:|---:|---:|
| 12 | 479,001,600 | 67 | 25,598,186 | 50,978,306 | 76,358,426 |
| 13 | 6,227,020,800 | 79 | 296,643,390 | 591,269,138 | 885,894,886 |
| 14 | 87,178,291,200 | 92 | 3,727,542,188 | 7,455,084,376 | 11,141,606,753 |
| 15 | 1,307,674,368,000 | 106 | 50,626,553,988 | 101,253,107,976 | 151,421,412,675 |
| 16 | 20,922,789,888,000 | 121 | 738,680,521,142 | 1,474,573,455,361 | 2,210,466,389,580 |

For these byte-valued states, assume n bytes per state and perfect distribution. The bitmap addresses the entire permutation domain, not only reached states. The following are idealized lower estimates before allocation/communication overhead and use decimal GB:

| graph | full bitmap alone | bitmap with 2 state banks | bitmap with 3 state banks | sorted-run hash batch with 3 banks |
|---|---:|---:|---:|---:|
| S14 | 10.90 GB | 115.27 GB | 166.88 GB | 289.68 GB |
| S15 | 163.46 GB | 1,682.26 GB | — | — |
| S16 | 2,615.35 GB | — | — | — |

The 2-bank bitmap estimate uses 2 adjacent layer rows; the 3-bank estimates use 3 adjacent layer rows. Hash batch includes 12 bytes per row for the separate exact sorted index (8-byte hash plus 4-byte bank-local row). Actual banks are allocated in segments, and current live sizes, per-rank skew and scratch can increase requirements. Existing open-address hash strategies have a different index overhead.

These figures make S14 Coxeter plausible on 8×180 GB B200 for both backends, but do not prove that it will run or finish. In the existing 2-bank bitmap implementation, the S15 Coxeter lower estimate already exceeds 1.44 TB, so it will not fit on this configuration without changing the state representation or using an out-of-core approach. The bitmap alone for S16 exceeds 1.44 TB. These are not universal limits for all graphs called S14/S15/S16, and repeated-symbol domains can be much smaller.

On actual hardware, the largest completed case in this evidence set is S13 Coxeter on 2×RTX 3060 using bitmap/warp: 6,227,020,800 states, 79 layers, all counts checked, with the last two exact sets checked. A 32-bit local row boundary was additionally checked by virtual mapping, not by a physical 2^32-row allocation. Per-rank capacities beyond that threshold and B200 runtime behavior remain unverified.
