# Segment metadata reserve retry: two GPU regression

A new segment can allocate successfully and then fail to allocate the per-shard owner metadata. Previously this caused RESOURCE_10 immediately, even if a smaller segment could fit. Segment plus metadata is now prepared transactionally: on metadata resource failure the uncommitted segment is synchronized and released, and a smaller one is attempted. A successful directory growth is not repeated during the retry. Other CUDA errors still propagate; if the minimum segment cannot fit, the job remains INCOMPLETE.

Tested on two physical RTX 3060, CUDA library SHA256 `c567135bde4bdf014b6137c90956f6ad44fd7f7fea8a2c075e3425213fdf970e`. Before: executable `82c40088a24bb8620a9fdc3e8272646546a41d49773739433bb6faa19c1198e3`; after: `a129f70af51906db3b464d0373793dac23fc9250e42b8dcbc9d5058a3ecf730b`.

The deterministic regression uses real CUDA allocations and an LD_PRELOAD hook that reports a simulated low-free-memory query once. The old binary stopped at depth 1 with RESOURCE_10; the fixed binary retried smaller segments and completed S5 with every layer count and the exact final two state sets matching the CPU oracle. Both ranks triggered the injected condition in the successful exact test. Seed admission and padded exchange also passed. When the low-free-memory result remained in force, the fixed binary stopped INCOMPLETE and the last completed layer's exact state set matched the oracle.

Further two-GPU checks passed: dense spill with exact and padded exchange on both backends; per-layer exact sets for atomic, warp and batch paths on S4, directed C6 and a repeated-symbol case; persistent-worker strategy switching; and a hard per-rank capacity stop. The filtered Rust segmented_history test passed. Evidence archive contains logs and metadata only, no state snapshots; SHA256 `15678a981fcbc0ae2a166140141ece059d042be6d945a14e42ac75bda7b43f1d`.

The updated Rust executable and matching CUDA library were tested together above. This source commit does not update the prebuilt GitHub native assets; installing an earlier wheel does not include this fix. No B200 execution or physical allocation of more than 2^32 rows on one rank is claimed.
