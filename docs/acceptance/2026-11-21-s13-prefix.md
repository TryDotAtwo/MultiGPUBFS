# S13 common heavy-layer window on 8×RTX 3060, 21 November 2026

Five prefix runs and one full-graph run cover all six strategy/backend combinations. The [full bitmap/warp S13 run](2026-11-21-segmented-s13-initial.md) was measured separately.

## Setup and correctness

Coxeter S13 (adjacent transpositions), identity start; eight RTX 3060 12 GiB on one PCIe host across two NUMA nodes, no NVLink. Source checkout `d067734f3e9f012e3e394ccf712f123867c00e0c`, executable SHA-256 `82c40088a24bb8620a9fdc3e8272646546a41d49773739433bb6faa19c1198e3`, CUDA library SHA-256 `c567135bde4bdf014b6137c90956f6ad44fd7f7fea8a2c075e3425213fdf970e`. Matching strategy implementation was committed at `17e3cfc11e269b77b9da796cc5c02c3c8d1fd1a1`; this benchmark predates the later post-allocation retry fix.

Common settings: balanced preset, eight shards, four owner lanes, exact exchange, batch 8192, queue 6144, configured per-segment maximum 2^32 rows/bank, initial allocated segment 1,048,576 rows/bank, autotune off. Prefix runs intentionally stopped after completed depth 44 and report `INCOMPLETE/PROFILE_LAYER_LIMIT`; this is not a complete graph time. All completed layer counts match independent Mahonian numbers. Full state sets were not compared for these prefix runs. The separate completed bitmap/warp run checked the full final two layers and cross-rank duplicates; its earlier layers were checked by counts.

The window contains 3,052,643,942 new states and 36,412,333,584 generated edges. These are single observations, not a distribution or a claim about B200.

The bitmap/warp row comes from the separate complete run and a simultaneous host transfer may have affected it. A/B bitmap and batch use different local shard mappings to give each word a single batch owner, so these timings compare complete strategies, not isolated atomic-instruction overhead. NVML values are maximum one-second samples, identical on all eight GPUs in these particular runs; short peaks can be missed. Tracked segment storage excludes queues, scratch, the bitmap itself, and CUDA/NCCL memory. For bitmap the separately allocated domain bitmap is 97,297,200 bytes per rank. Hash batch's peak index allocation was 1,509,949,440 bytes per rank; its peak state-and-index storage is included in the tracked figure.

The hash batch window was approximately 34% slower than hash warp in this one run, while its sampled peak memory was lower.
