# dev42 eight-GPU autotune and CayleyPy acceptance

This is a development prerelease. The default backend is still `legacy`; choose
`segmented24` or `permutation_bitmap` explicitly. These results do not establish
B200 or S14 acceptance.

## Package and regression

The [dev42 release](https://github.com/TryDotAtwo/MultiGPUBFS/releases/tag/native-pip-20261122-v42)
contains the exact wheel used in the installed-package check below. Its SHA-256 is
`2ba8d7bd644b7f3cf0afc30c1b503cc6518493b8d7701a2f026991339d02a204`.
Python source is commit `3e2df9d7325694144d4c3c46acc6089817bfcf02`;
the reused native executable is SHA-256
`10cb2e53915b9e8936582889445eed263cd6c370ab877aae0ee628fd8f2da687`,
and the SM86 CUDA library is
`ca4fba4419120aaa4a37123e56faedbb91c8e4b58e263481e9a15b517c43d908`.
The release native bundles are those of dev41.

The change fixes a segmented autotune admission error caused by treating a
capacity from an earlier memory snapshot as a user request in a later admission
call. Segmented pilots now pass the actual caller-specified capacity; measured
pilots and user limits remain active. Replaying a recorded inventory with 2 MiB
less free memory per rank reproduced the old rejection; that reduction was
synthetic and is not a measurement of the original memory fluctuation. Four
regression cases failed before the patch and passed afterward. The
[packaging run](https://github.com/TryDotAtwo/MultiGPUBFS/actions/runs/44951982034)
passed 82 tests plus two subtests. The independent repository-wide native
contracts workflow remains red at `cargo fmt --check`; its earlier check steps
passed. Do not interpret the packaging run as a green repository-wide CI.

## Installed wheel through CayleyPy

Host: eight RTX 3060 12 GiB, SM86, driver 580.178.04, PCIe/NUMA host, exact
exchange. `balanced`, autotune on, 1,048,576 rows per allocated segment bank;
the configured upper segment limit remained 2^32. One persistent group was
used across all four jobs, and all eight worker PIDs stayed the same. Times
are single observations, not repeated performance comparisons.

| Backend / strategy | Graph | Completed states / diameter | BFS s | API wall s | Measured pilots | Oracle |
|---|---|---:|---:|---:|---:|---|
| bitmap / atomic | S12 | 479,001,600 / 66 | 106.021 | 217.723 | 7 | all 67 layer counts |
| bitmap / atomic | S9 | 362,880 / 36 | 0.490 | 14.987 | 11 | all layer counts |
| segmented hash / warp | S10 | 3,628,800 / 45 | 1.393 | 33.801 | 11 | all layer counts |
| segmented hash / warp | S9 | 362,880 / 36 | 0.227 | 11.778 | 11 | all layer counts |

The independent Mahonian oracle checks every recorded layer size and the
factorial total. This installed-wheel check did **not** compare full
intermediate-layer state multisets. Persistent workers were reused, but
autotuning still ran for these distinct jobs; worker reuse is not a promise of
zero per-graph preparation or tuning.

The [exact check script](artifacts/2026-11-22-dev42-cayleypy-installed-check.py)
is recorded verbatim, including its original temporary paths and package-path
assertion; adapt those paths when reproducing it elsewhere. Machine-readable
[measurements and per-rank receipts](artifacts/2026-11-22-dev42-8gpu.json)
include the actual profile, allocation and runtime identifiers. Full source and
installed-run logs were retained in three SHA-256 identified archives; their
hashes are in the JSON.

## Direct S12 preset checks

The same SM86 native artifact and fixed Python source were also run with
bitmap/atomic, eight shards and four owner lanes, autotune enabled, on the
same eight-GPU host. These are single observations at distinct preset
geometries, not an equal-capacity comparison or a claim that max_capacity has
a measured larger maximum graph.

| Preset | Completed states | BFS s | API wall s | Window depths 28–38 s | Pilots / common depth |
|---|---:|---:|---:|---:|---|
| balanced | 479,001,600 | 69.428 | 169.148 | 36.567 | 3 / 21 |
| max_capacity | 479,001,600 | 215.376 | 316.404 | 110.465 | 3 / 19 |

Every layer count matches the Mahonian oracle, and full state sets of the last
two layers were checked without duplicates. The remaining intermediate
state multisets were not compared. For balanced the worst reported
`peak_live_rows` was 9,640,704 per rank; bitmap bytes were 7,484,400 per
rank. Reported storage, queue and reserve byte receipts are in the JSON;
these are not a measured instantaneous VRAM peak. The result does not prove
the physical allocation or traversal of 2^32 rows in one segment.

For independent context, earlier
[installed dev41/native SM86 tests](2026-11-21-dev41-package-sm86.md)
cover two-GPU full small-layer multisets, collisions and capacity, plus
eight-GPU communicator/session failure injection. The separate
[queue-geometry evidence](2026-11-22-queue-8gpu-evidence.json) includes
three S12 bitmap repetitions at each of two geometries; both queue and batch
change, so the observed time difference cannot be attributed to either one
alone. None of these tests proves all graph families or every fault schedule.
