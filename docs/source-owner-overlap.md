# Immutable-source generation overlaps preceding owners

The all-owner event waits are placed after next-bank source generation/regeneration, before the owner-error vote and receive-inbox reuse. The next source bank and parent snapshot are independent of the preceding shard owner kernels. Bank A/B alternation keeps the preceding source immutable; older owners have already retired before a bank is reused. The final round still waits for every owner before the layer vote and frontier commit.

Actual two-GPU byte/int64, collision, matrix, skew-retry and current/previous resource oracles passed. This establishes correctness of the event dependency schedule. No profiler trace or isolated overlap speedup is claimed. The earlier6.29x result predates this scheduling change and covers a different combined checkpoint.

The bounded tuner now considers1/4/16 shards and a4-shard quarter-batch alternative, skips inadmissible alternatives and compares identical completed prefixes. Neither these four candidates nor a short prefix prove a global optimum for every frontier size or hardware topology.
